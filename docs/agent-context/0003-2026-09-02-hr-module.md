# HR / time-tracking module ("Recursos Humanos") — 2026-09-02

Delta handoff. Builds on [0001](./0001-2026-06-10-full-project-context.md)
(full project) and [0002](./0002-2026-06-10-logos-cards-outsourcing.md).
Covers the 3-phase HR module.

---

## What it is

Employees clock **in / out / break / lunch** each day by scanning a QR that
**rotates every 10 min** on a shared workplace screen, from their own
logged-in phone. Admin creates employee profiles, invites them by email to set
their own password, configures each one's **schedule**, and watches an
**attendance dashboard** that flags late arrival, early departure, over-long
break/lunch, missing clock-out, and absences.

**Employees are a 4th user population** (after admin, company, station), kept
disjoint the same way stations are.

## Auth / routing (4th population)

- Service `lib/services/employees.ts`. `fetchEmployee(supabase, userId)` returns
  null for non-employees (RLS self-read) — used to gate shells.
- `(app)/layout.tsx` redirects employees → `/empleado` (parallel to the station
  redirect). New `(employee)/empleado/layout.tsx` ejects non-employees.
- `admin_list_users` RPC now also excludes `employees` (they don't leak into
  `/admin/users`).
- Invite flow mirrors the company activation pattern: admin action creates the
  auth user with the **real email confirmed** + a random unshared password
  (`auth.admin.createUser`), stores a single-use `activation_token`, and emails
  `${origin}/activar-empleado/<token>` via the existing `sendEmail`. The
  employee sets their password (`auth.admin.updateUserById`) at
  `app/activar-empleado/[token]/`. Resending the invite doubles as a password
  reset.

## QR punch (Phase 2)

- Kiosk = a shared screen at `/rrhh/kiosko/<access_token>` (public, secret-link
  gated — no admin session on the wall). Client polls
  `getCurrentKioskTokenAction` and renders a QR (the `qrcode` npm dep) of
  `${origin}/empleado/marcar?t=<punchToken>`. Token TTL = **10 min**
  (`hr_qr_tokens`); a new one is minted when the last expires.
- Employee scans → `/empleado/marcar` (under the employee gate). `recordPunchAction`
  validates the token is unexpired + the transition is legal (state machine in
  `lib/services/hr-punches.ts`: `deriveState` / `nextActions`), then inserts an
  `hr_punches` row (service client, `employee_id` from the verified session).
- Admin manages kiosks in the **Kioscos** tab of `/admin/rrhh` (create, reveal /
  copy / rotate the secret link, open, activate/deactivate, delete).

## Schedules + dashboard (Phase 3)

- `employee_schedules` (one row/employee: `workdays int[]` 0=Sun..6=Sat,
  start/end time, lunch/break/grace minutes, tz). Edited via the **Horario**
  (clock) button per employee → `saveEmployeeScheduleAction`.
- `lib/services/hr-attendance.ts` — **pure** `computeDaySummary(punches, schedule,
  {weekday, isPast})` → worked/break/lunch minutes + `flags[]`
  (`late | early | long_break | long_lunch | missing_out | absent`). Unit-tested
  (12 cases). `missing_out`/`absent` only fire for past days.
- Dashboard `/admin/rrhh/asistencia` (day-selectable, defaults to today):
  per-employee entrada/salida/worked/break/lunch + flag badges, and an alerts
  banner. Linked from the RRHH header.

## Timezone

All day-bucketing + schedule comparison is **America/Costa_Rica (UTC-6, no DST)**.
Helpers in `hr-punches.ts` (`crDayRangeForDate`, `crToday`, `crWeekday`,
`addDaysStr`) and `hr-attendance.ts` (`crMinutesOfDay`). **Never call `Date.now()`
in a server component render** — the `react-hooks/purity` lint rejects it; read
the clock inside a lib module and return the result (see `crToday()`,
`fetchPunchToken().expired`).

## Gotchas / open items

- **Buddy-punching**: the rotating QR proves *presence at the screen*, not the
  scanner's identity — a photo of a fresh QR forwarded within 10 min still works.
  Geolocation / selfie is possible future hardening (not built).
- **Kiosk link is a secret** (like station links); rotating it invalidates the
  old URL.
- Deactivating/deleting an employee: an inactive employee is bounced from
  `/empleado` to `/login` (login never redirects an authed user, so no loop).
- `qrcode` (+ `@types/qrcode`) added as deps.
- Not yet built: multi-day/week hour rollups, CSV/export, per-weekday schedule
  overrides, overtime as an explicit flag.
